# Activity submissions, grades, and automatic classroom access

Migration `supabase/012_activity_uploads_grades.sql` adds written/file activity types, positive maximum points, allowed JPEG/PNG/PDF formats, private submission files, numeric scores, and grading timestamps. Existing activities remain written responses worth 100 points; existing feedback is retained without inventing grades.

Teachers configure the submission type, allowed formats, and total points. Those settings and the linked lesson lock after the first submission. Teachers can download submitted files and save a score (including zero) with feedback. Students see only their own status, grade, and feedback in activities and in the work dialog. Reviewed work cannot be overwritten by a student; teachers can correct a grade.

File submissions accept one file up to 10,000,000 bytes. The browser checks extension and JPEG/PNG/PDF signatures. Storage is private and limited to these MIME types and size. The database checks the authenticated recipient, assignment access, upload ownership, path, allowed format, storage metadata, and reviewed state before linking a file. Files are downloaded as attachments; there is no inline document execution. File signatures and declared metadata are not a malware scan. Failed registration attempts clean up unlinked uploads when possible; orphaned objects may still need operator retention cleanup after record deletion or network failure.

A class code enrolls a student immediately. Published lessons assigned to that class and their activities become visible to new members without enrollment approval, whether published before or after joining. Draft lessons remain private. A lesson must have a class or direct student assignment before publication. Teacher class lists now exclude former student memberships in classes owned by someone else. AI-use authorization remains separate from academic class membership.

The sample class **Grade 9 Mathematics — Activity Practice** was created for the existing lesson owner. The existing linear-equations draft was assigned to this class and published; two additional practice activities (written and file upload, 20 points each) were created. No students were silently enrolled and no real student grades were created. The operator can share the class code shown in Classes & people for testing.

Verification: `npx tsc --noEmit`, `node scripts/verify-activity-submissions.mjs`, invitation regression checks, production build, and public deployment checks. PostgreSQL tests cover teacher ownership, private grades/files, zero/invalid scores, reviewed-work locks, immutable scoring settings, file registration integrity, automatic enrollment access, former-member teacher class lists, and anonymous/legacy route denial. Browser QA covers written submission, teacher grading, student grade badges, file type configuration and PNG submission/download in the isolated preview. A real teacher/student account test is still needed to verify live Storage transport with actual school sessions; database policies and live sample creation were verified separately.

The local preview stores test attachments in browser storage and has a 1 MB attachment limit. The authenticated application uses Supabase private Storage and a 10 MB limit. Demo identities and grades are never cloud account credentials or real school records.
